# 分组与事项

分组用于分类和组织，事项用于执行和结束。两者共用现有树、行内编辑、拖拽、标签与右侧详情，不增加独立的分组管理页面。

## 组织与转换

- 分组可包含分组、事项、笔记和事件，不限制合法的嵌套层数；禁止把节点移入自身或其后代。
- 有子项的事项不会自动转成分组。项目仍是有明确结果的事项所用的可选标记。
- 原地转换保持身份、正文、子项、标签、已记录投入和历史；不自动转换已有节点。
- 原始估计与已失效的提醒／审视安排保留为历史，转回事项时恢复；不会重新开启已失效的提醒或审视。
- 正在计时或仍有执行安排的事项，需要先明确处理相应安排才能转为分组，不能静默停止计时或清除安排。
- 分组不接受新的自身计时、补记、完成、交接、估计、计划开始、截止、重复或执行提醒。已有历史投入仍可查看、更正、删除和恢复。

## 展示与统计

- 分组没有待启动、进行中、完成勾选或自身计时按钮。
- 空分组显示“暂无事项”；下面有内容但没有未结束任务时显示“暂无待办”。
- 概况显示待办数量、其中逾期数量及子项计时情况。逾期和计时属于待办的情况，不与待办数相加。
- 分组、笔记与事件不计作任务完成数。任务按实际身份计数，嵌套汇总每条投入只累计一次。
- 转换前的自身投入明确标为“历史直接投入”，与子项投入分开，保留投入总量及原始时间段。

## 筛选与接口

- 全部事项可以展示空分组，并按名称、标签或类型查找分组。
- 执行、截止、今日重点、完成等视图只匹配实际任务；分组可作为匹配子项的上级路径展示，但不增加匹配数量。
- 最后一个匹配子项结束后，不符合条件的分组路径也消失；保留当前编辑项的既有临时机制。
- 分组中的子任务保持自己的状态、计划与截止，分组不会产生虚假的父级执行约束。
- AI 和本机 API 使用相同的类型与命令规则；可以在分组下创建和整理事项，不能对分组发起执行操作。
- 同步、备份和恢复保留分组身份与层级；不支持分组的旧版本必须明确拒绝新数据，不能降级解释或静默丢弃。

## 验证场景

覆盖空分组、嵌套分组、全部关闭、子项逾期、交接、正在计时、历史直接投入、拖拽循环保护、不同筛选与保存视图、AI/API 非法执行拒绝、导出导入与重启持久化。原生验证仅使用隔离的合成数据，结束后退出全部测试窗口和托盘。
