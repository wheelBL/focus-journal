# Windows 统一工作区（0.30.1 起）

普通启动使用 `%USERPROFILE%\.focus-journal`，与 EXE 所在目录、当前工作目录、快捷方式和启动父进程无关。Electron 的 `userData` 和 `sessionData` 在单实例锁及任何数据库初始化之前一起固定。macOS 沿用已有目录。

采用这个位置是因为 Windows 可能把从 MSIX 应用启动的进程所访问的 AppData 重定向到应用缓存；仅写死 AppData 的字符串路径不足以保证访问同一文件。

首次启动会检查原标准目录及 Windows 应用缓存中的专注记工作区。业务数据相同的副本可直接采用；发现不同的有效日志时必须明确选择，不能按数量或日期猜测。损坏或不完整的旧目录会阻止创建空白工作区。遇到 AppData 重定向时，先通过 Windows 的独立进程启动接口重新进入；失败则停止，避免使用错误缓存。

迁移前取得来源工作区的单实例锁；旧版本正在使用它时要求先退出。迁移采用复制方式：SQLite 通过备份接口包含 WAL，其他持久文件保留，包括历史备份、浏览草稿、本机偏好和加密配置及其 Chromium `Local State`。不会解密 AI 或同步密钥。已知缓存及临时锁文件不复制。校验原库及副本逐条一致后才写入 `workspace-location.json` 并原子发布目标目录，随后重启使用新目录。原目录保留。

后续只打开已完成初始化的统一工作区。用户目录另有 `.focus-journal-bootstrap/active-workspace.json` 登记工作区身份；即使整个数据文件夹被移走，也能区分既有工作区与首次安装。登记不匹配、标识、数据库或必要记录缺失时停止并说明原因，不回退旧副本或重新生成默认数据库。启动日志记录逻辑目录、物理目录及是否使用显式工作区，方便定位。

`--data-dir <目录>` 保留为明确的独立工作区入口；它不会触发个人数据迁移。演示和 QA 必须同时指定独立目录。内部迁移参数只接受已发现的专注记旧目录，不接受任意目录。

升级后请使用新版 EXE，更新仍指向旧版的快捷方式。旧版程序本身不具备统一目录规则；原目录保留用于恢复，不应继续用旧版本编辑。工作区是本机 SQLite，不宜放在网盘同步目录；跨机器使用应用的日志同步。

验证覆盖目录重定向、冲突副本、源文件变化、缺失或损坏数据库、WAL、设备文件和草稿、原目录保留、显式 QA 隔离；真实 Electron 使用合成密钥验证迁移后解密、重启及独立 Windows 启动，测试完成退出辅助进程。
