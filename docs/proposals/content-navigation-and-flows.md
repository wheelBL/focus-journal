# 任务、笔记、提醒：导航与操作动线

日期：2026-11-02。

状态：用户已确认三个独立入口、共享分组，并授权持续实现。本文记录设计依据；0.33.0 按这些动线实现，验证结果另行记录，不代表已完成用户长期试用。

## 设计目标与边界

保留紧凑列表、任意嵌套、Things 风格及夜间模式、今日时间线、现有任务身份和投入历史。让“要做什么”“要查什么”“什么时候提醒”各有明确入口，同时能在原地处理关联内容。

分组负责归属；子任务表达工作拆解；关联笔记表达参考信息。这三种关系不能只用一个展开箭头表达。现有混合树在实现时必须保留原关系、路径及历史，不在导航改版中自动搬迁或转换记录。旧的跨类型父子关系如何投影，须用真实边界样例验证后制定兼容规则。

## 固定导航

左侧保留一套稳定的主入口，不再同时提供重复的顶部模块入口与另一套页面入口。下面的视觉分段不是需要点开的菜单。

| 导航分段 | 始终直接可达的入口 | 职责 |
| --- | --- | --- |
| 开工与整理 | 今日、收件箱 | 执行首页；集中整理捕获内容 |
| 内容 | 任务、笔记、提醒 | 分别执行、阅读编辑、安排和处理提示 |
| 时间与回顾 | 日历、回顾 | 时间安排与投入记录；周期复盘 |
| 通用工具 | 快速记录、搜索、设置 | 跨内容能力；AI 保留当前上下文入口 |

分组树是任务、笔记、提醒共享的范围选择器，不新增“分组管理”必经页面。三类页面用相同的范围位置和路径显示当前分组。日历保留已有事件和投入，不新增第四个内容入口来容纳事件。

窗口变窄时保留当前范围及详情返回入口；用可收起侧栏或详情代替多层模态框。常用创建、开始计时和提醒处理不因宽度缩小而进入三级菜单。

## 分组与页面状态

1. 初次进入内容页默认“全部分组”。选择 MDE 后，任务显示 MDE 的任务，切到笔记或提醒继续查看 MDE 的内容；标题旁始终显示范围，并有一次操作即可清除的入口。
2. 选分组只限制当前内容列表。分组详情在右侧给出任务、笔记、提醒的分项概况；点击相关内容可直接预览，避免为了查看一条资料而切换整个模块。
3. 三个内容入口共用明确显示的当前分组，各自记住筛选、排序、选中内容、展开状态、阅读位置与草稿。位置按“模块＋范围＋视图”保存，不能把一个分组的滚动偏移强加到另一个分组。
4. 今日、收件箱、日历、回顾默认各有自己的范围，不静默继承 MDE。返回内容页恢复之前的范围；明确进入一个保存视图时采用它的范围并显示出来。
5. 无结果只表示当前范围和条件没有该类内容。提供“在此新增”和“查看全部分组”，不自动跳页、不偷偷清除过滤条件。

## 各入口的主要呈现

| 入口 | 主列表 | 常用动作 | 右侧详情 |
| --- | --- | --- | --- |
| 任务 | 紧凑任务树；分组作为上下文；默认隐藏已结束任务 | 行内修改、创建同级/子任务、直接计时、完成、计划与截止 | 任务信息、计时、相关笔记和提醒、投入与复盘 |
| 笔记 | 标题与短摘要；分组与标签；列表密度可保持紧凑 | 直接编辑、搜索、关联任务、从选中文字生成任务 | 正文阅读编辑；必要时扩大阅读空间 |
| 提醒 | 待处理在前，其次按下一次时间排列；暂停或停止的安排通过筛选查看 | 确认本次、稍后提醒、直接改时间及重复、打开来源 | 独立提醒内容，或原任务/事件的关联信息 |
| 收件箱 | 按捕获顺序连续整理，清楚标注类型 | 改类型、选分组、必要安排、保存并下一条 | 当前条目的完整编辑区 |

任务附带提醒与独立提醒在提醒入口统一列出，但标明来源。查看、确认、稍后提醒都作用于原安排，不生成第二条任务。停止提醒与删除原任务是两个动作。确认提醒不改变完成状态，也不结束计时。

笔记不显示待启动、截止或计时列。分组不显示完成框。提醒的时间不冒充任务截止。任务列表里的普通父任务仍代表工作，不自动按分类容器处理。

## 主要用户动线

### 1. 正在工作，临时想到一件事

全局快捷键或固定快速记录按钮 → 输入 → 保存并返回原窗口。沿用已有前缀和语义解析，不要求先进入任务/笔记/提醒页面。全局捕获默认进入收件箱，目的地明确显示；不能默默继承后台打开的某个分组。

在内容页点“在此新增”则预选当前类型和分组；明确创建子任务时预选当前父任务。全局捕获与在当前位置新增是两种清晰的入口语义。

### 2. 整理收件箱

每日提醒卡片“整理收件箱” → 打开独立收件箱 → 点选内容 → 在右侧调整类型、归属及必要时间 → 保存并下一条。

归属选择允许搜索完整分组路径，不必逐层展开多级树。跳过仍保留未整理状态；保存失败保留输入和当前条目。保存成功后列表移除已整理条目并选择下一条；没有剩余内容时呈现整理完成，不跳去其他模块。提醒卡片本身的确认不把内容批量标为已整理。

### 3. 执行任务时查看笔记

任务行直接开始计时 → 右侧“相关笔记”点开一条 → 在同一个详情区阅读或编辑 → “返回原任务”。任务列表、滚动位置和计时均保持不变。

右侧是一个可返回的详情区，不叠加“任务弹窗 → 关联管理弹窗 → 笔记弹窗”。从笔记打开另一个关联对象时保留清楚的返回路径；关闭相关内容返回最初的选择。

### 4. 看笔记时发现一件需要做的事

选中文字或使用笔记编辑区的“生成任务” → 就地填写任务名称，预选笔记所属分组 → 保存。

笔记保留，新增任务与笔记建立关联。保存后可继续写笔记，也可直接开始新任务的计时。普通“生成任务”不把整篇笔记转换或删除；确需改变内容类型时使用单独的转换动作并说明影响。

### 5. 为任务设置或处理提醒

任务详情的“提醒” → 同一编辑区选择时间和是否重复 → 保存。已有提醒直接点时间修改，不经过“更多安排 → 重复安排 → 编辑”链条。

到点后的卡片直接提供确认、稍后和查看来源。查看来源优先在主窗口的详情区打开，不要求先跳到提醒列表再查找任务。未保存的原编辑保留，不能被提醒窗口覆盖。

### 6. 创建和处理独立提醒

提醒入口“新增提醒” → 名称、时间、可选重复和分组 → 保存。时间是必要输入，重复在同一表单内展开，不需要先建任务再转换。

提醒列表或卡片上直接处理本次。未到时的条目点时间即可编辑；停用/删除放在次要操作。下次时间与循环规则同时可见，避免把“停止重复”误认为删除历史或完成事项。

### 7. 从今日、日历或搜索找到内容

今日仍承担重点、继续计时与今日进展，不复制笔记管理或提醒管理。今日任务可直接查看关联信息；日历中的任务、事件或提醒直接打开相应详情。

全局搜索按任务/笔记/提醒标明类型与完整路径。选结果先在当前位置预览，明确选择“前往所在位置”才切换模块、范围和列表位置。退出搜索恢复原编辑上下文。

## 操作深度与键盘规则

以下是设计目标，尚非测量结果。“入口次数”不包含输入文字；保存、确认和返回应单独计数，避免用含糊的“两步完成”掩盖实际成本。

| 目标与起点 | 进入操作的目标 | 返回要求 |
| --- | --- | --- |
| 任务行 → 开始计时 | 行内一次点击，不先打开详情 | 列表不跳动 |
| 已打开任务 → 查看一条相关笔记 | 点击可见标题一次 | 一次返回原任务 |
| 内容页 → 新建本类型内容 | 一个明显入口或快捷键 | 保存后留在原范围 |
| 任务详情 → 修改提醒 | 点击提醒时间一次，时间与重复一起编辑 | 保存后留在原任务 |
| 提醒卡片 → 确认/稍后 | 卡片上直接操作一次 | 原工作窗口不被迫切换 |
| 收件箱 → 调整归属 | 一个可搜索的选择器 | 保存并下一条，无额外管理页 |

常用开始、完成、正文编辑、提醒时间和处理本次不依赖右键菜单。右键与快捷键提供同一操作的快捷入口；转换、删除整支等低频或有较大影响的动作保留清楚的影响说明。

保留现有任务树的 Enter、Tab、Shift+Tab、Insert、重命名及计时快捷操作，但只在树或对应编辑器获得焦点时生效。笔记正文中的 Tab/Shift+Tab 服务于正文，不移动整篇笔记的归属。Ctrl/Cmd+Enter 在当前表单执行明确标注的保存；Escape 优先退出最内层临时菜单或编辑态，保留草稿，不连续清空内容。返回键和 Alt+Left 在可返回的详情流程中具有一致语义。

## 连续性与失败处理

- 切换入口、打开关联内容、全局搜索和临时返回保留草稿、选中对象、光标与阅读位置；计时不随导航停止。
- 草稿保留与成功保存分开显示。保存失败继续显示错误并允许重试，不自动跳到下一条，不把失败当成整理完成。
- 保存中的内容防止重复提交；迟到的保存结果不能关闭后来打开的编辑器。切换到其他内容后，结果只更新原记录。
- 修改后不再符合当前筛选的条目，在编辑结束前保留并解释原因，之后按视图规则退出；显式完成或删除后的焦点去向保持可预期。
- 记住每个入口的工作位置。共享分组不会共享一份选中行或滚动位置。
- 不新增鼠标轨迹或键盘记录来测量层级；沿用操作、入口、结果和版本。步骤目标通过明确的场景走查验证，不能从单条业务操作日志推断用户实际点击次数。

## 后续验证范围

用 MDE 的任务、关联笔记和独立提醒走查上述七条路径。重点覆盖：三级以上分组、旧混合树中笔记下仍有任务、一个笔记被多项任务引用、没有某类型内容的分组、保存视图与范围切换、保存中出现提醒、失败后返回继续编辑。

接受标准是：无需为了完成同一目标反复离开当前模块；常用操作不多于一个编辑层；返回后可以接着工作；来源记录只有一份；已有任意嵌套关系和投入不丢失。小窗口、键盘、夜间与减弱动效模式需在后续交互稿中一起验证。

下一步制作仅覆盖这些动线的可交互稿，再依据走查结果确定页面细节和迁移方案。本轮没有改动正式版、运行测试应用或发布构建。
