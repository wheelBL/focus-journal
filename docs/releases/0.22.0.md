# 专注记 0.22.0

已经工作了一段时间才想起计时，现在可以补入实际开始时间并继续同一条计时。

1. 从事项开始计时，或选择“先计时”。
2. 在计时卡片、事项详情或底部计时栏打开“调整开始时间”。
3. 选择“40 分钟前”等快捷时间，或输入准确日期和时间。
4. 保存后，过去的投入计入累计，从现在再专注本次目标时长才提醒。例如先补入 40 分钟，再专注 25 分钟，届时累计 65 分钟，计时继续到主动结束。

暂停不消耗目标时间，调整暂停中的记录不会自动恢复。已有暂停片段保留，事项和父级投入、实际开始、今日与日历同步更新；跨午夜会分别计入对应日期。计划开始、截止时间、原始估计和事项完成状态不受影响。

取消不写入；保存失败保留输入并说明原因。拒绝未来时间、越过第一次暂停、单次超过 24 小时的调整，以及与同事项已有投入重叠；不同事项并行计时仍受支持。已结束的投入继续使用“校正”。

本机 API 增加 `focus.set-start`；`focus.start` 和 `focus.start-unassigned` 可直接传 `startedAt`。共享业务规则，保留修订检查和幂等重试。详见 [API 文档](../../desktop/docs/local-api.md)。

保留 0.21.1 的放弃投入、恢复和保存进展流程。首次打开旧数据会先创建 SQLite 备份再升级到 schema 17；既有记录、ID 和时间线保留。跨设备同步请将各设备更新到 0.22.0 或更新版本，旧版不能读取新数据结构。

完整解压 `FocusJournal-0.22.0-Windows-x64.zip`，先退出旧版托盘，再运行目录中的 `专注记.exe`，无需安装 Node.js。

验证：222 项核心、147 项界面交互、15 项本机 API、2 项同步、4 项预览 Worker 测试通过；另有隔离 Electron 的 8 项真实指针操作与窗口尺寸检查、14 项 Windows 打包运行检查。生产包与 QA 包的 13 个应用构建文件逐字节一致。测试完成后，QA 剩余进程与窗口均为 0。
