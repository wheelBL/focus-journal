# 0.31.0 — 可嵌套分组与统一 Windows 工作区

纯分类不再需要伪装成待完成事项。可以在原有树中创建任意嵌套的分组，或将已有事项原地转为分组，保留身份、子项与投入历史。

## 分组

- 右键新增分组、新增子分组或转换类型；沿用行内编辑、拖拽与键盘层级调整。
- 分组没有自身的完成勾选、计时、计划、截止或重复安排，显示下面事项的待办、逾期与计时概况。
- 本周、截止、执行等视图只匹配实际任务，分组仅作为必要的上级路径。最后一个匹配事项关闭后，路径随之消失。
- 分类转换前的直接投入保留在日历和投入复盘中，与子项投入分开说明；汇总不重复累计。原始估计保留为历史，转回事项时恢复。
- 正在计时或仍有执行安排时会明确提示先处理相关安排，不静默停止计时或清空日期。
- AI 与本机 API 支持创建、组织分组，并拒绝对分组计时、完成或安排任务计划。

## 数据与升级

数据结构升级至 20，升级前自动创建 SQLite 备份。不会自动转换旧项目或事项，也不会改写既有投入。跨设备使用分组数据时请将客户端升级到 0.31.0 或更新版本；旧版无法打开新数据。

本次包含 Windows 统一工作区修复：正常启动固定使用用户目录下的 `.focus-journal`，不同 EXE 位置、命令行、Codex 和资源管理器入口读取同一份数据。首次迁移校验并保留原目录；存在不同旧工作区时需要明确选择；缺失或损坏的工作区不会被当成新空白日志。

升级前退出旧版，解压完整 Windows ZIP 后运行“专注记.exe”。不要只移动 EXE。测试使用独立的合成数据，个人数据库、设备密钥和测试输出不进入发布包。

## 验证

- 348 项业务与数据回归、275 项界面交互测试、19 项本机 API 测试、2 项同步传输测试、4 项预览 Worker 测试通过。
- 覆盖 41 层分组、循环拖拽拒绝、截止边界、交接后退出待办、历史投入恢复与转换撤销。
- 数据结构 19 升级至 20 的测试确认全部业务记录不变，并核验原库备份。
- Windows 实际发行代码通过 30 项操作、7 项重启检查；正式与 QA 包 37 个业务文件一致，测试结束后窗口和进程均为 0。
- macOS 15 的 Apple Silicon 与 Intel 原生机器均通过构建、领域及平台测试，各通过 17 项真实应用操作和 7 项重启检查；正式与 QA 包业务代码一致，测试窗口退出。详见 [GitHub Actions 验证记录](https://github.com/wheelBL/focus-journal/actions/runs/41316432197)。这验证主要运行流程，不替代各用户设备上的系统权限与兼容性检查。

Windows 包未做代码签名；macOS 包签名和系统要求沿用 README 中的说明。

macOS 两种架构的安装包均可从上述 Actions 运行的 Artifacts 下载。已有 Windows 与 Apple Silicon Release 资产保留，Intel 包直接使用 Actions 产物，不再重复上传。
