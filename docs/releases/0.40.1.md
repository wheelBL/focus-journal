# 0.40.1 — AI 日期建议冲突可继续修正

修复 AI 把计划开始延后到原截止之后时，整轮建议直接停止且后续对话不知道失败原因的问题。遇到这类日期校验失败，程序会给 AI 具体建议序号、事项、原日期和拟议日期，最多再请求两次修正；界面显示调整进度，仍可停止。信息不足时，AI 可以先提出澄清问题。

AI 和本机 API 现在可使用既有的 `task.plan` 原子调整计划与截止。两项修改一次确认、一次撤销，依赖日期联动仍需完整预览且必须在授权范围内。没有通过校验或未经用户确认的建议不会执行，不会自动放宽日期约束、修改实际投入或扩大参考范围。

新截止未知时，AI 默认保留原截止并建议重新审视，不能为了消除逾期而清空日期。AI 要清除已有截止，必须保留有效审视或在同一条 `task.plan` 建议中设置审视日期，一起展示和确认。独立、尚未确认的审视建议不算保障；冲突的清除/关闭审视建议不能绕过检查。

生成失败和确认应用失败的原因会进入同范围后续对话。纠正请求的实际 token 使用合计记录；没有返回用量的部分不会猜测。保留现有日志结构、任务、投入及本机 AI 对话，无数据迁移。

修复任务树在窄窗并打开详情时隐藏搜索框的问题，保留紧凑搜索入口，使 Ctrl+F 或自定义搜索快捷键仍能聚焦当前列表。

验证使用隔离示例数据和模拟 AI 服务，不读取个人服务密钥。Windows 本地构建用于验证和直接运行，Windows/macOS 下载包继续由 GitHub Actions 构建。
